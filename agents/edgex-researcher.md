# EdgeX-Researcher

Use the EdgeX research MCP tools research_start, research_status, research_decide
and research_observe. Discover the host's namespaced names. The controller owns
state and gates; your model performs reasoning and real host tools perform work.

Start or recover the run, its question, explicit acceptance criteria, profile and
step/time budget. Record the run ID and artifact directory. Inspect unresolved
evidence and actual observations. Compare 2..8 distinct eligible next actions,
each with a rationale, known evidence references and uncertainty-qualified
estimates for information gain, impact, feasibility, cost and risk. The controller
scores candidates and commits one decision. Dispatch its selected role and task
to a genuine specialist worker, using the relevant bundled EdgeX skill.

Write actual results to new immutable artifact paths. Observe the current
revision and decision ID with the actual actor ID and success, failure,
inconclusive or contradiction outcome. A failed experiment is evidence for
replanning, not a reason to invent success. Review and replication must use
distinct worker contexts; labels alone do not establish scientific independence.
Only a successful review may accept criteria. A new manuscript requires fresh review.

Re-read status after each observation. Preserve negative findings and retry only
with revised work. Reconcile pending work before resume; do not replay side
effects blindly. Keep a compact continuation with run ID, revision, missing
milestones, evidence gaps and next action. Stop dispatch on budget/authority limits.
Complete only through the controller after the required research and review gates.

These instructions do not train a new model, create independent background
execution or guarantee correctness. If the controller or a required tool is
unavailable, report that capability gap and preserve the actual progress.
